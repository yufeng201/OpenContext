---
name: validate-design
description: Validate OpenContext design or contract changes across PRD, technical rules, executable examples and user journeys. Use after changing selectors, plugin instances, output ownership, retrieval freshness or documented interfaces; not to implement a feature.
---

Run from the OpenContext repository root containing package.json and AGENTS.md. Follow [development workflow](../../../docs/DEVELOPMENT.md) and [design index](../../../docs/README.md).

1. Read the changed rule and its requirement/acceptance IDs. Locate matching types, JSON configuration and user flow before editing.
2. Keep the same rule in all affected documents. If a pure rule changed, extend tests/design/semantic-fixtures.ts.txt with both permitted and refused cases. This is a design fixture, not production code.
3. Run `pnpm check:docs` and `pnpm test:harness`, then `pnpm check` for the final change. Do not run real connectors or model calls.
4. Report checked examples, failed or missing coverage, and remaining implementation tests. Never turn a proposed E2E into a claimed passing application test.

Canonical skill source is this file under .agents/skills. The identical .claude/skills copy is generated by `pnpm sync:skills`; verify with `pnpm check:skills`. Do not edit the generated copy or modify client permissions. No Hook is required.
