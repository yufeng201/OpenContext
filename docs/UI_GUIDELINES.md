# UI 与交互约束

适用自托管管理后台；这是实现前的最小规范，未有视觉稿或可用性测试。[前端架构](FRONTEND_ARCHITECTURE.md)定义技术分工，[用户流程](USER_JOURNEYS.md)定义操作与验收。

## 导航与默认路径

以“来源、文件、搜索、任务、设置”为主要入口；Space/project 始终可见。首次进入展示“添加仓库/上传文件 → 查看同步 → 搜索 → 打开原文”；embedding、设备和 Wiki 加工为渐进选择。Repo Wiki 用官方预设表单，高级配置才展示实例、DAG、挂载和 JSON。

信息页显示名称、来源、更新时间、版本与下一动作；不要让普通用户理解 fencing token 或内部 SQL。诊断 trace/实例锁版放可展开详情。

## 状态与风险

| 情况                    | 展示与动作                                                                                                      |
| ----------------------- | --------------------------------------------------------------------------------------------------------------- |
| 加载/空结果             | 骨架或明确加载；空结果区分未同步、可诊断的索引/解析问题和无命中。对普通查询者不泄露无权文件存在                 |
| worker 离线、来源已更新 | 原文可读；标派生结果 stale，默认按 freshness 策略过滤；显示等待设备/重试。allowDegraded 不能放过 invalid 或撤权 |
| 发布与索引              | 内容已发布、索引 pending/partial/ready、外部发布 unknown 分开显示，不使用一个“成功”覆盖所有阶段                 |
| 引用                    | 显示来源、path-at-commit、revision、片段与 freshness；打开固定版本，当前权限拒绝时不换成别的正文                |
| 纠正/取代               | 展示适用 scope、准确原/新 revision、原因和可撤销关系，不让 authored 一律压过来源事实                            |
| 冲突/删除               | 显示影响范围和 base/current/proposed；用户确认不替代服务端 CAS/ACL/所有权 gate；未发布候选单独标识              |

## 视觉、无障碍与内容

使用语义 token：background/surface、foreground/muted、border、primary、success/warning/destructive；任务状态同时用文字/图标，不能只靠颜色。间距用 Tailwind 的统一步进，字体层级先限定正文、标签、标题、代码；首版浅色与系统主题策略统一，后续再扩主题。

表单都有可关联 label、错误说明和提交中状态；键盘能完成向导、搜索、打开文件和确认操作。对话框管理焦点、Escape 与返回焦点；长列表分页后再按测量决定虚拟化。检查对比度、焦点可见性和窄屏可读性；这些要在真实页面用测试验证，文档本身不算通过。

Markdown/来源文件默认禁用原始 HTML，URL 允许列表与外链提示；文件名不能当作可执行路径。复制 citation 使用准确版本；错误展示安全 correlationId 与恢复按钮，不渲染秘密或原始 provider 错误全文。无需人工批准每个授权 derived 产物，高风险外部发布和人工所有权变更单独处理。
