# Offline live-acceptance evidence gate

`node scripts/live-gate.ts verify REQUEST.json EVIDENCE.json` performs bounded **offline consistency checking**. It never starts Codex/Claude, calls a provider, opens a network connection, discovers credentials/history, changes client configuration, or writes a transcript. Only the two explicitly named regular files are read; symlinks, unknown properties, raw CLI streams and unsupported client versions fail closed. CLI rejection prints a fixed error without the offending path/value. The caller must provide already reviewed synthetic or sanitized input; schema validation cannot detect every secret hidden inside arbitrary prose.

The authority is `RequestSchema` / `EvidenceSchema` in [live-gate.ts](../scripts/live-gate.ts), using the existing CitationSchema. The client adapters accept only `opencontext-sanitized-live-evidence/v1` envelopes identifying Codex **0.151.0** or Claude Code **2.1.280**. These are the locally inspected version/help releases, **not validated raw-export adapters or authenticated model sessions**. Upgrading requires explicit format/version fixtures. Do not rename a raw JSON stream into this format. Full Session import and a CLI stream are different formats.

`importServerAudit` projects an explicitly supplied existing server AuditEvent: reader role only, supported search/read action, non-null request/project and consistent outcome. Actor and unrelated metadata are discarded. The existing audit is best effort and has no response body hash. A future authorized collector must capture the scoped MCP response independently, associate its server requestId with the client callId and fresh provider session, and supply its exact read text/citation. Missing or ambiguous linkage fails this checker. Submitted records remain unsigned; even a perfect match cannot establish genuine provider/account execution. A self-written audit envelope is not independent evidence.

## Recall acceptance

1. A contains only an approved synthetic fact. Export only that newly created session into an explicitly chosen file, review it, and import through the existing Session/publish gate in an independently configured test instance. No discovery of old sessions. Preserve the published fileId, revisionId, commitId, path, sourceVersion, contentHash and citation URI as a separate expected record.
2. B must be newly created: distinct from A and every supplied prior session ID, not resumed, with zero prior messages. Its prompt must omit the expected fact. Keep A, gold evidence, repository contents and other files outside the model work directory. The declarations in this offline format require independent session-start attestation before a live claim.
3. Capture actual ordered context_search then context_read calls. Search must contain the exact file/revision pair, read arguments must pin that pair, and every event must join exactly one audit by requestId/tool/project/code/file/revision. Duplicate call/request IDs, missing audits, other tools or wrong project fail. Read text must hash to the expected SHA256 and contain the fact. All citation fields must match, including commit and sourceVersion.
4. Answer claims explicitly link to the read callId; each quoted fragment must occur in both its actual read response and the answer, accompanied by the exact citation URI. An answer-only assertion cannot pass. This checks literal evidence consistency; a human must still assess completeness and semantic accuracy, including uncited prose.
5. Success of these predicates returns `DRY_RUN_CONSISTENT` without an authorization/budget record, or `OFFLINE_CONSISTENT` with one. **Both always return liveProof=false and BLOCKED_INDEPENDENT_CAPTURE_AND_AUTHENTICITY**, including provenance=submitted. Synthetic positives never mean live passed.

## Revoke and failure acceptance

Use a further fresh session C after a separately authorized token/source revocation. Include all A/B IDs in priorSessionIds. Expected denial must be UNAUTHORIZED, FORBIDDEN or NOT_FOUND with matching actual audit results; failed service scenarios use TIMEOUT or INTERNAL_ERROR. Every event must return the expected code, with no text/hits/citation; answer must be empty and claims absent. Cached bytes already delivered to a provider cannot be remotely recalled. For upstream Feishu token/ACL loss, existing published local archives are not automatically revoked; test explicit local binding revocation separately. No automatic upstream ACL mirror is claimed.

## Limits and authorization

Files are capped at 256 KiB each before JSON parsing (bounded read protects against growth), envelopes at 256 KiB, aggregate event JSON at 32 KiB, per-read text at 8192 characters additionally constrained by that byte budget, 8 tool events, 120000 ms and 6 observed calls. These are **offline import ceilings**, not approval, provider runtime control, USD billing enforcement, or a permission to make 6 calls. No scheduling, retry, proxy, fallback or live launch is implemented.

A provided authorization record requires approvalId, paidEgressApproved=true, maxCalls/maxInputBytes/maxToolBytes/maxElapsedMs/maxUsd and externalCostEnforcement=true. Observed evidence exceeding its bounds is rejected. Its claims of approval or cost enforcement are not independently proven. Multiple files/runs must be accounted by a future collector before any forwarding; this single-envelope checker cannot enforce a global paid budget. Missing explicit user authorization, validated export adapters, collector, isolated identity, external cost cap or complete new-session capture leaves live execution blocked. Neither guessed default budgets nor command templates grant authorization.

## Inert client command templates

These are reviewable argument outlines from local CLI help, **not commands run by the gate**. All paths and authentication must be explicitly supplied externally for a separately approved isolated client; never read/copy global configuration or existing private history. No credentials are included here.

- Codex: `codex exec --json --ephemeral --sandbox read-only --cd EXPLICIT_ISOLATED_DIRECTORY PROMPT`. MCP must be configured only through a separately supplied explicit isolated configuration, whose supported syntax/version must first be validated. Read-only shell does not prevent private reads; external filesystem/tool isolation and a genuine provider cost cap are prerequisites. No `mcp add`, resume, automatic auth discovery or global writes.
- Claude: `claude --bare --print --output-format stream-json --verbose --tools "" --strict-mcp-config --mcp-config EXPLICIT_REVIEWED_CONFIG --max-budget-usd EXPLICIT_APPROVED_CAP PROMPT`. `--bare` does not reuse existing OAuth; explicit API authentication is an external prerequisite. Validate actual config/header/environment expansion without exposing a key before using it. Do not select a proxy, bypass permissions or create credentials. A supported flag in help does not prove runtime configuration works.

No raw client export is supported today. A future adapter must retain fresh-session identity, actual tool call IDs, request correlation and exact returned revisions/hashes while dropping headers, credentials, unrelated messages and private transcript metadata; add captured synthetic supported-format fixtures and incompatible-version negatives before enabling it. Neither installed CLI nor this checker proves an authenticated Agent end-to-end result.

## Verification scope

Harness positives cover both supported envelope versions, missing authorization dry-run, bounded approved envelopes, denied/revoked/error sessions, server audit projection and explicit safe file reads. Negatives cover reused/resumed/nonempty sessions, leaked fact, answer-only claims, reversed tool order, head substitution, changed content, fabricated commit/call association, wrong scope, missing/duplicate audits/calls, unsupported formats/versions/extra secret fields, duration/call/input bounds, plaintext or answer after denial, owner audits, symlink/oversize input and CLI error redaction. `pnpm check` also runs all existing business/contract/build checks. These are synthetic offline checks, not browser, live provider, real Feishu or Linux/container execution evidence.
